# 实现决策

## 注册卡辑或调整存档格式

**存档中的整数编号来自内容键。** 未指定编号的扩展包使用 `owner/key`，单卡使用 `owner/key/art`。这些键限用 ASCII 字符，以 FNV-1a 计算编号，所以加卡或调整显示顺序不会给旧物品改号。册内顺序单独记录。传奇的瘦包、肥包和整盒有专门的配货规则，不能按普通卡辑的 `slots` 推算。v0.7.0 快照仅列瘦包张数；核对该版本时还须按当时的肥包 9 张、瘦盒 12 包、肥盒 6 包保护未拆包装。[编号](../../ProbablyTradingCards/CardSeries.cs) · [传奇配货](../../ProbablyTradingCards/StationLegends.cs) · [发布标识校验](../../scripts/SeriesCheck/PublishedIdentities.cs)

**一次注册失败不能留下半辑。** 注册器先检查整辑的卡号和包号，再写入系列、卡牌和包装索引。扩展在游戏主线程的 `OnEnable` 登记整批嵌入资源，停用时释放返回的句柄。若同键卡辑已被另一实例重新登记，旧句柄延迟释放只能撤销原对象。玩法扩展查询的是有实体身份的单卡，返回品相 0、1、2 分别为折痕、轻磨、完好。[注册器](../../ProbablyTradingCards/CardRegistry.cs) · [对外接口及用法](外部模组接口.md)

**册页顺序与原版库存节点序号是两回事。** 原版用广度优先顺序给非物品节点编号，新增一页会让旧卡套的序号后移。读档时按保存的实体卡找到当前卡套。原版还会用存档覆盖工厂设置的类别与标签，普通 C 卡的日用品分类因此在解码后补上。物品特性单独保存在节点列表之外，测试往返时按 `parentItemUniqueId` 将特性挂回对应实体。[卡套恢复](../../ProbablyTradingCards/AlbumPocketRestore.cs) · [原版物品接入](../../ProbablyTradingCards/NativeItems.cs) · [旧册页回归](../../tests/Extensions/AlbumSaveChecks.cs) · [原生读档测试](../../tests/NativeValidation.cs)

## 鼠标、册页与图片

- **点击何时生效。** 默认激活在鼠标按下时执行，卡包和单卡查看使用普通激活，让原版先判断拖拽以及单击或双击。原版允许查看未买入的非彩票 `DOCUMENT`，因此单卡使用这个标签。美工刀的目标谓词按 OR 合并，追加对卡包的处理可保留动物、鱼等原有目标。背包空间不足时，传奇原封包已写入的异画结果要保留，以免跨日重试重新抽取。[交互与开包流程](物品与存档.md) · [美工刀接入](../../ProbablyTradingCards/CutterIntegration.cs)
- **文字和卡套的尺寸。** 原版 `TagElement.SetText` 每次写字都会重设换行，刷新卡名后须重新应用换行设置。布局按未缩放的边界居中，放大卡套后要补偿锚点偏移，否则显示位置与落点不一致。八卡位跨页测试选第三张和第五张，分别覆盖左、右叶。[册页布局](../../ProbablyTradingCards/SeriesAlbum.cs) · [卡名与落点测试](../../tests/NativeValidation.cs)
- **同一张卡可以对应不止一幅图。** Eleanor 的一个异画卡号可切换两幅画，导出校验也要覆盖油画素材。扩展卡的品相图标使用 `--wear-` 分隔，清单的系列键和素材键都不允许双连字符；另一张完好卡拼成的图名可以恰好以 `_wear_0` 结尾。原版 Debug 物品面板在库存校验前就读工厂的精灵，因此工厂返回前要完成物品校验。[物品工厂](../../ProbablyTradingCards/NativeItems.cs) · [纹理与命名回归](../../tests/test_series_art.py)
- **校验完成后再写成品。** 扩展原画先在输出目录内的临时目录生成，所有卡面和包装通过检查后才逐文件替换成品。这保证输入或图像校验失败时保留原成品；替换多个成品本身分多次完成。[导出器](../../scripts/export_series.py)

## 顾客、交易与剧情回调

- **来客顺序由原版决定。** 固定送货的码头散货商在普通客流前安排。原版当天先递减冷却，再按列表顺序抽普通客人，所以预排送货和自然到访设置不同的冷却值。展示柜邀请放在列表尾部，只使用剩余名额。发行商的对话页有三个选项位置，每页最多两张货单，余位用于翻页。黄牛用存档 run ID、周数和货位生成随机序列，让同周读档保留包装内容；单卡的候选还取决于玩家当时缺哪些卡。[客流规则](../design/顾客与展示柜.md) · [发行商](../../ProbablyTradingCards/CardCustomers.cs) · [黄牛货单](../../ProbablyTradingCards/CardScalperRules.cs)
- **谁负责结算。** 发行商用 `TemporaryBuying` 表示进货溢价，让它随原版成交清理而结束。收藏悬赏的收购预览只读物品实例编号，成交时才分配编号并记录交付。原版已经算好普通售价，第三张的稿酬另付，此时清空预算会触发原版告别。[发行商成交](../../ProbablyTradingCards/CardCustomers.cs) · [悬赏回调](../../Examples/CollectionBounty/ModEntry.cs) · [成交与重复交付测试](../../tests/Extensions/BountyChecks.cs)
- **何时解除预约。** 玩家主动送客表示取消，关店时原版自动送客保留预约。卖出收藏簿或外层容器时，原版 `SellItem` 只回调外层物品，因此还要核对随容器转手的预约卡实例。卖掉同款的另一张卡不影响原预约。[预约实现](../../ProbablyTradingCards/RareCardAppointments.cs) · [柜台成交回归](../../tests/NativeValidation.cs)
- **在哪个游戏事件判定结果。** Georgio 的借款告别要到玩家选定金额后才生成，异画标记挂在实际告别回调上。拾荒则等原版放完普通和扫描仪战利品，借唯一一次 `MarkBackpackFound` 调用追加掉卡；定位不到唯一调用时保留原流程。[剧情判定](../../ProbablyTradingCards/AlternateCardProgress.cs) · [拾荒入口](../../ProbablyTradingCards/ScavengedCardDrop.cs)

## 哪些验证需要真实游戏

**离线测试的边界。** Smoke 将作者示例清单直接嵌入测试程序集，用于检验独立卡辑注册，不依赖主模组当次打包的卡辑。离线宿主没有 Unity 场景来运行 `Awake`，因此先初始化物品目录字典，再调用真正的注册和查询方法。用于查询身份和绑定图标的实体只准备必要标签；预设 `DOCUMENT` 可以避开 Unity 的形状重绘。完整工厂的缩略图和真实落点由游戏内检查覆盖。[Smoke 输入](../../tests/Smoke/Smoke.csproj) · [离线目录](../../tests/Extensions/NativeDirectoryChecks.cs) · [离线实体](../../tests/Extensions/Program.cs) · [原生检查](../../tests/NativeValidation.cs)

**验证会写入当前玩家状态。** 编码物品和查看异画分别会修改当前存档的特性表和模组进度，因此在副本上验证，最后恢复原引用。故障注入测试单独留存一份玩家状态，即使被测清理路径失败，也能还原库存、现金和日期。测试零运气时要抵消随身物品的加成，以便带有赌徒硬币的测试档也能复现同一边界。[故障恢复与运气边界](../../tests/NativeValidation.cs)

**命令回执与启动日志。** 模组的 `OnEnable` 返回后，加载器才将它标为运行中。验证桥先查询 `HasInstance`，因为读取 `PlayerStore.Instance` 可能创建玩家。模组写入 JSON 时，CLI 有机会读到半份文件；命令间用操作系统锁互斥，进程退出后锁随之释放。若回执写入遇到占用，桥只重试发送已得结果。CLI 以 UTF-8 写标准输出，供 Windows 管道读取中文 JSON。[验证桥](../../tests/NativeAgentBridge.cs) · [CLI](../../scripts/game_verify.py)

追加写入的启动日志可能包含多次审计，只取最近一次。加载器的组合指纹来自清单与 DLL，贴图另作逐文件核对。回归用原版 `ModFingerprint.Compute` 对固定输入算出的已知值作期望，避免用被测代码验证自身。[试玩检查](../../tests/playtest.py) · [指纹样本](../../tests/test_playtest.py)
