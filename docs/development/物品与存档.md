# 物品与存档

卡包、整盒、单卡和集换册都是原版库存里的实体物品。原版处理交易、现金、所有权和库存位置，模组在物品上记录原版无法从外观推断的卡牌信息。

## 找到一件物品的状态

| 对象 | 存在哪里 | 排查时看什么 |
| --- | --- | --- |
| 未拆卡包 | 物品的 `PackDataTag`，内容为 `CardPack` JSON | `contents` 保存基础卡与初始品相，`tearRolls` 给每张卡保留一次手撕判定。`resealed` 和 `seal` 分别记录是否二封和玩家能看到的封口线索。 |
| 原封整盒 | 物品的 `BoxDataTag`，内容为 `CardBox` JSON | `packs` 按顺序保存每个内包。拆盒时读取这组内包，盒内的保底卡在配货时就已确定。 |
| 实体单卡 | 目录物品 ID、卡种和品相标签、原版价格特性 | 卡种编号对应系列清单里的定义，品相特性修正估值。Eleanor 异画所选画面随物品的 `spritePath` 保存。 |
| 集换册 | 原版容器内的子物品 | 从册中取出的就是放进去的那张卡。星港收藏簿的页码随册保存，异画发现记录则属于整个存档。 |

`NativeItems.Register` 为每种卡的三个品相分别注册物品工厂。卡包 JSON 和实体卡共用卡种编号。扩展辑的清单可指定卡牌 `id`，省略时由作者模组 ID、系列键和素材键生成。收藏位按本辑清单顺序排列。[卡种编号](../../ProbablyTradingCards/CardSeries.cs)、[物品注册与存取](../../ProbablyTradingCards/NativeItems.cs)、[卡包记录](../../ProbablyTradingCards/CardGame.cs)

## 从按下鼠标到完成拆包

1. 卡包使用原版普通激活。默认激活处理器会在鼠标按下时触发，早于拖拽判定。单卡查看也走普通激活，并使用原版 `DOCUMENT` 标签，让玩家能在成交前查看卡面。[卡包交互](../../ProbablyTradingCards/NativeItems.cs)、[单卡查看](../../ProbablyTradingCards/CardInspection.cs)
2. 手撕和美工刀最终都进入 `NativeItems.TryOpen`。包装须已归玩家所有并放入库存。用刀时，刀也须已拥有并放入库存。美工刀向原版目标判断和使用回调追加卡包处理，以保留刀具原有用途。[美工刀接入](../../ProbablyTradingCards/CutterIntegration.cs)
3. 读取卡包时先校验规格、内容和随机记录。传奇卡包首次开启还会读取当天的剧情与活动条件，并在放置单卡前写回异画结果。即使空间不足，跨日重试也沿用这次判定。[异画判定](../design/异画与收藏簿.md)
4. 生成的单卡或内包逐件尝试放入玩家库存，再尝试后柜台。只要有一件放不下，就销毁本次生成的所有物品，保留原包装。全部放入后才销毁包装，并记录本次抽到的异画。[开包与放置](../../ProbablyTradingCards/NativeItems.cs)

## 存取后表现不一致

如果读档后**价格变了**，除了物品节点，还要检查按实例 `uniqueId` 恢复的品相特性。发行商进货加价属于 `TemporaryBuying`，成交后原版会移除，转售时从该规格的基价重新计算交易修正。[发行商供货](../../ProbablyTradingCards/CardCustomers.cs)、[原生存取测试](../../tests/NativeValidation.cs)

原版读档会用存档中的标签和分类覆盖工厂默认值。解码后，模组会为已恢复的 C 级普通单卡补日用品分类，册内卡也走同一流程。[分类恢复](../../ProbablyTradingCards/NativeItems.cs)

物品的名称、描述、风味和所选卡面由原版物品节点保存。读档先调用物品工厂重建交互与容器结构，再还原节点中的文本和图像信息。原生往返测试核对这些信息与保存前一致。[原生存取测试](../../tests/NativeValidation.cs)
