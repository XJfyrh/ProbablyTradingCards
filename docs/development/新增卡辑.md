# 新增一辑卡包

在主项目的 `ProbablyTradingCards/Series/<key>/` 下增加一份清单和一组原画，就能随主模组发布一辑普通卡包。游戏按清单抽卡、注册三档品相的单卡、排列收藏簿卡位，并在发售后将本辑加入发行商货单。下面的命令都从仓库根目录运行。要独立发布，请使用配套作者模板、完整前置发布包和本机游戏。[《码头来信》作者模板](../../Examples/DockLetters/README.md)

## 用两张卡跑通第一包

示例《码头来信》有两张卡、每包两个卡位，第 2 天开始供货。复制含清单和卡面的示例目录即可试做。第一次导出需要 Python 和 Pillow，构建需要 .NET SDK 和本机游戏安装。[美术工具环境](../../scripts/README.md) · [构建说明](../../README.md) · [完整示例清单](../../Examples/DockLetters/Series/dock_demo/series.json)

```powershell
Copy-Item -Recurse -LiteralPath 'Examples/DockLetters/Series/dock_demo' -Destination 'ProbablyTradingCards/Series'

.\.venv\Scripts\python.exe scripts/export_series.py dock_demo
dotnet run --project tests/Smoke/Smoke.csproj -c Release
dotnet build ProbablyTradingCards/ProbablyTradingCards.csproj -c Release
```

导出成功会显示 `dock_demo: verified 2 card faces, icons and packaging`。Smoke 输出末尾的 `Registered series` 应包含 `dock_demo`。构建会将卡辑清单嵌入 DLL，并把阅读图和图标放入发布包。

## 换成自己的卡辑

复制示例到新的 `Series/<key>/` 目录，将清单中的 `key` 改成目录名。每张卡放一张含卡框的 2:3 PNG，例如 `art` 写 `fare-ticket` 就放在 `Art/fare-ticket.png`。准备好原画后，用自己的目录名运行导出命令。

| 在清单中填写 | 游戏怎样使用 |
| --- | --- |
| `key`、`name` | `key` 用小写字母开头，可含数字和下划线。同一模组内每辑各用一个键。`name` 是货单、包装和收藏簿上的中文或其他显示名称。 |
| `releaseDay`、`packValue` | 正整数。发行商每周二到访，从达到发售日的第一次到访起供货。包价是原封包的转售基价，发行商的报价为基价的两倍。 |
| `cards` | 每张卡填写 `art`、`name`、`rarity`、`value` 和 `flavor`。素材键在本辑内唯一，可用小写字母、数字和分隔用的连字符。五档稀有度为 C、R、SR、SSR、UR。基价取正整数。`subject` 可选 `Item`（默认）或 `Character`。 |
| `slots` | 数组中的每一项代表包中的一张卡。先按权重选稀有度，再从本辑该档中等概率抽一张。权重用正整数。连续抽取可以重复。 |
| `customPackArt`、`customAlbumArt` | 默认复用现成包装。自绘时将对应字段设为 `true`，在清单旁放透明背景的 `pack.png` 或 `album.png`。 |

示例的 `"slots": [{"C": 1}, {"C": 3, "R": 1}]` 表示首张必为 C，第二张有 75% 概率为 C、25% 为 R。本辑用到的每个稀有度都要能从至少一个原封卡位抽到。需要自定义二封包时，可另设等长的 `resealedSlots`，省略时沿用 `slots`。[夜话的原封与二封配置](../../ProbablyTradingCards/Series/night_stories/series.json)

卡包编号由模组 ID 和系列键生成。单卡编号还使用该卡的素材键 `art`。展示卡号和收藏簿沿用 `cards` 的排列顺序，相邻且稀有度相同的卡放在同一组册页。

如果 Smoke 报告编号冲突，先按报错路径找到清单。卡包冲突时，可换系列键，或显式填写尚未使用的卡包编号 `packKind`（整数，从 3 起）。单卡冲突时，可换该卡的素材键并同步改名原图，或显式填写尚未使用的非负整数卡牌 `id`。

## 保留已有卡和原封包

游戏存档保存物品 ID、已生成原封包的内容和物品的贴图路径。给已有卡换图时沿用素材键，替换该键对应的原画。卡名、说明、出率和卡位顺序可以独立调整。改动卡包每包张数会影响已存入存档的原封包。

构建会对照 `ProbablyTradingCards/series-identities.json` 检查编号、包内张数和贴图键。新增卡或卡辑后，用下面的命令生成新清单，并在提交前审查差异。删除或替换现有标识前需要核对已有物品和原封包能否继续读取。

```powershell
dotnet build ProbablyTradingCards/ProbablyTradingCards.csproj -c Release -p:UpdateSeriesIdentities=true
```

## 在游戏里验收

将生成的 `ProbablyTradingCards/dist/ProbablyTradingCards` 安装到游戏的 `Mods`。从本辑发售日起，在发行商来访的周二与他对话，选本辑，买一包卡和一本收藏簿。《码头来信》最早可在第 2 天买到。拆开应得到两张卡，右键阅读可看大图，把卡拖到专属收藏簿中对应的卡套即可收录。[安装与进货](../../ProbablyTradingCards/README.md)

提交卡辑时带上清单、原画和导出的 `Textures/Cards`、`Textures/Items` 文件。打包前会检查主项目所有卡辑的纹理。只想核对文件时，运行 `.\.venv\Scripts\python.exe scripts/export_series.py --check-core`。F9 验证包还能检查发行商供货、实体开包、入册与存取。[测试与试玩](../../tests/README.md)
