# 给《可能是集换卡牌》做外部模组

前置模组 `probably_trading_cards` 提供卡辑注册和实体卡查询接口。普通卡包可直接使用[《码头来信》作者模板](../../Examples/DockLetters/README.md)。自定义收购、成套奖励等玩法可从[《收藏悬赏》源码](../../Examples/CollectionBounty/ModEntry.cs)开始。

## 一个扩展从哪里取得图片和卡牌

每个扩展分别打包自己的 `manifest.xml` 和 DLL，提供卡辑的扩展还要带上自己的贴图。清单的 `Prerequisites` 中填写 `<Mod>probably_trading_cards</Mod>`，工程引用前置 DLL 时设置 `Private=false`。玩家将前置和扩展分别装入 `Mods`，启用后按提示重启。玩法模组可以只依赖前置，通过实体卡查询接口识别其他作者的卡牌。

一辑卡由**作者模组 ID 和系列键**共同标识。例如，两个模组可以各有一辑 `dock_demo`，其中各有一张素材键为 `ticket` 的卡。游戏从各自登记的模组读取卡牌图标、阅读图和自绘包装，从前置读取默认包装、收藏簿内页和磨损遮罩。引用另一位作者的卡辑时使用模组 ID 和系列键，翻译显示名不会影响引用。

## 内容作者的注册入口

导出的作者工程已经实现下面的流程。首次制作自己的模组时设置作者、模组 ID、显示名及 DLL 名称。后续添加卡辑只需在 `Series/<系列键>/` 放置清单和卡图，再运行 `dotnet build -c Release`。构建会用前置 DLL 实际读取清单，并检查所需美术。示例工程和工具可以一起导出到独立 Git 仓库。[导出模板与构建](../../Examples/DockLetters/README.md)

| 公开成员 | 用法 |
| --- | --- |
| `TradingCardsApi.RegisterEmbeddedSeries(ownerId, assembly)` | 普通内容包使用此入口。在 `OnEnable` 传入自己的程序集，保存返回的 `IDisposable`，在 `OnDisable` 调用 `Dispose()`。有一辑校验失败会撤销本次整批注册。 |
| `TradingCardsApi.RegisterSeries(ownerId, seriesKey, json)` | 在游戏主线程的 `IMod.OnEnable` 调用，传入 `Init` 收到的 `manifest.ID`。整辑校验通过后返回 `CardSeries`。发行商从达到发售日的首个周二开始供货。 |
| `TradingCardsApi.UnregisterSeries(ownerId, seriesKey)` | 在 `OnDisable` 撤销本模组已登记的系列。返回值表示是否移除了一辑。 |
| `TradingCardsApi.TryGetSeries(ownerId, seriesKey, out series)` | 查找特定作者的一辑卡。可选内容缺席时返回 `false`。 |
| `TradingCardsApi.RegisteredSeries` | 读取已登记的卡辑。遍历 `series.CardIds` 和 `series.Cards[id]`，可按册页顺序列出定义。读取其他作者的内容时，选择进店、打开页面等游戏已完成启动的时机。 |

同一作者重复提交系列键或编号与其他卡牌冲突时，错误会指向相应清单。前置自带的夜话、传奇和外部的《码头来信》都通过 `RegisterEmbeddedSeries` 加载。模板作者可以直接复用示例的启停代码。[内容模组入口](../../Examples/DockLetters/ModEntry.cs)

## 玩法作者怎样识别玩家手里的卡

```csharp
bool BuysCharacter(GameItem item) =>
    TradingCardsApi.TryGetCard(item, out var card, out int condition) &&
    card.Subject == CardSubject.Character && condition == 2;
```

这段规则接受任意作者的完好人物卡。`TryGetCard` 核对实体单卡的目录标识、卡种和品相。品相 0、1、2 分别表示有折痕、轻微磨损、完好。返回的定义还提供 `Series.OwnerId`、`Series.Key`、`Art`、`Rarity` 和 `Value`。两张同款卡共用定义。要分别记录交付，成交时调用各自的 `GetUniqueID()`，取得原版分配给该实例的编号。

在原版买家的 `willAcceptItem` 中查询能否收购。需要记录交付、发奖励时，在该买家的 `onItemBought` 成交回调中更新本模组的存档数据。这样玩家预览卡面、询价或撤回报价时都能保留原有悬赏进度。示例接受三张人物实体卡，同款的不同实例也可以交付。[实际买家与奖励](../../Examples/CollectionBounty/ModEntry.cs) · [实体卡查询实现](../../ProbablyTradingCards/TradingCardsApi.Items.cs)

## 改动后怎样验证

内容作者在自己的项目目录构建即可检查清单、卡位权重和 PNG。主项目维护者运行以下命令，用两个外部示例检查公开接口。游戏另装时，在末尾加 `-GameDir '游戏目录'`。美术导出所用的 Python 需装 Pillow，可以用 `-PythonExe` 指定解释器。

```powershell
./tests/Extensions/run.ps1
```

游戏内验收用新档。第 2 天向发行商购入《码头来信》，首张必出末班信差。第 3 天把人物卡卖给星港人物志编辑。第三张成交时，核对现金增加了本次报价加 120 信用点，卡片从库存移出，编辑结束收购。三张可以搭配不同系列，也可以分几次周三来访交齐。[独立包安装](../../Examples/DockLetters/README.md) · [原生验证与试玩](../../tests/README.md)
